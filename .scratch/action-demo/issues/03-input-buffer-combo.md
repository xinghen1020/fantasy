## Comments

- 2026-10-03 实现完成，22/22 绿（combat_rules 12 + attack_dummy 6 + player3d 回归 4），仅剩人工可玩项。规则：派生窗口=后摇段（CONTEXT.md 定义）；派生表写入每招 `"next": {输入类型 → 下一招}`（票04 重攻击分支直接加键）；单槽缓冲——窗口外只存最新输入、窗口开启瞬间消费、无派生弃置（连段到头不循环、缓冲不带入自由态故无鬼魂输入）。0.5s 缓冲生命期为防御性上限（当前所有招的窗口距离 < 0.5s，正常流程必先消费；防未来长前摇招式）。
- API：`start_attack` 保持"仅自由态直接起手"语义（02 的单测原样通过）；玩家输入走新入口 `notify_light_pressed()`，按 自由起手/窗口内直接派生/其余缓冲 三路路由。
- 收招动画：每招可选 `recovery_animation`，后摇段播放，消除 02 时期的"动画播完后摇定格"观感。库内 `Sword_Regular_C` 无独立 `_Rec`，暂复用 A_Rec，观感不对再下动画。
- 数值占位：2/3 段伤害 12/16，第 3 段前摇 0.3s / 后摇 0.6s（收招更重）、前冲降为 2.0；全部待 08 调参。
- 2026-10-03 试玩反馈"第三个动作有点问题"，排查确认：standard_2 库内 `Sword_Regular_C` 时长 2.0s（A 0.43 / B 0.53），逐帧截图核实其内容为"助跑→跃起→摔倒"，根本不是挥砍——该库命名不可信。第3段换用 `Melee_Hook`（0.47s，同族节奏单发打击），数值回归常规段（前摇0.25/后摇0.5），收招暂复用 A_Rec。备选（08 调参/换素材时参考）：standard/Sword_Attack 1.53s（真挥砍但长，需数据表适配节奏）、Sword_Regular_Combo 3.0s、Sword_Heavy_Combo 4.33s（票04 重击素材候选）。22/22 绿。
- 2026-10-03 修正：第3段动画恢复使用 `Sword_Regular_C`（owner 决定，且经逐帧核实它实为"跃进下劈"终结技：助跑0-0.4→腾空0.4-0.6→下劈落地0.6-0.85→地面收势0.85-2.0，此前"非挥砍弃用"的判断有误）。数据表按剪辑实际打击时刻重排：windup 0.55 / active 0.3 / recovery 1.15，总长 2.0s=剪辑长度不掐帧；recovery_animation 置空（剪辑自带收势）。原理解说明：动画按剪辑原速原长播放，招式窗口=数据表三段之和，两者独立；招式结束时切走动画。播放机制与逐帧采样结论已记入本注释。22/22 绿。
- 2026-10-03 试玩反馈"动作结束后闪现一段距离"：根因是 Mixamo 剪辑烘焙了 hips 骨骼位移（模型自己会跑），物理体只有 lunge 在推，动画结束回 Idle 时骨骼归位产生闪现。修复采用**引擎根运动**（Godot 4.3+ 内建，owner 选定）：动作期间 `root_motion_track = %GeneralSkeleton:Hips`（root_motion_local），tick 里 `velocity = basis * get_root_motion_position() / delta`；自由态关闭抽取（保留走路起伏）；剪辑无根位移或编辑器测试（动画不推进）时回落数据表 lunge_speed 兜底。实测：面朝 +X 位移 +0.175m（A 剪辑 hips 位移量），方向/量级与动画一致。位移所有权部分转移至动画（spec 前冲条款已同步修订）。
