# Spec: 类怪物猎人动作系统可行性 Demo

Status: ready-for-agent

## Problem Statement

独立开发者想做一个俯视角动作游戏，核心押注在类怪物猎人的角色动作系统上（动作承诺、连段派生、翻滚闪避）。但这个押注目前只是直觉：仓库里只有一个能走跑、挥一下剑的角色，没有战斗判定、没有硬直、没有反馈。开发者不知道这套动作系统以自己的独立开发成本（依赖 Mixamo 现成动画、无专职美术）是否做得出来、做出来手感是否成立。在下重注做完整游戏之前，需要一个小而完整的垂直切片来回答"可行吗？好玩吗？"。

## Solution

一个最小可玩的战斗验证场景：玩家角色拥有一套带动作承诺的招式系统（轻攻击 3 段连段、可派生的重攻击、带无敌帧的翻滚、输入缓冲），对着一个木桩输出完整命中反馈（顿帧、击退、伤害数字、血量），并用一个定时触发的尖刺陷阱代替敌人来验证翻滚 i-frame 和受击反馈。倾斜俯视角跟随相机，3D 模型 + Mixamo 动画。像素化渲染等表现层目标明确推迟——本 demo 只回答动作系统的问题。

## User Stories

1. As a 玩家, I want to 用 WASD 八方向走动和跑动, so that 我能在场地中自由走位
2. As a 玩家, I want to 按下轻攻击键后角色进入有前摇的攻击动作, so that 攻击有可感知的发起成本
3. As a 玩家, I want to 轻攻击最多连出 3 段不同动作, so that 连续点按有节奏感而不是重复同一招
4. As a 玩家, I want to 按下重攻击键出一个独立于连段的重招, so that 我有高投入高回报的选择
5. As a 玩家, I want to 在轻攻击连段中段派生出重攻击, so that 招式之间能组合出分支路线
6. As a 玩家, I want to 在连段中提前按下一键、招式到位后自动接上（输入缓冲）, so that 连段不断手感
7. As a 玩家, I want to 翻滚期间不受到敌方判定伤害（无敌帧）, so that 我能"穿"过攻击而非只能跑开
8. As a 玩家, I want to 翻滚取消攻击的后摇但不能取消前摇, so that 我有逃生阀但攻击仍需预判（动作承诺）
9. As a 玩家, I want to 攻击期间锁死移动、位移由招式自带前冲提供, so that 每一招都有可预判的走位结果
10. As a 玩家, I want to 攻击命中时画面短暂顿帧, so that 命中有"打到了"的分量感
11. As a 玩家, I want to 命中时木桩被击退一小段, so that 我看到攻击对目标的作用力
12. As a 玩家, I want to 命中处飘出伤害数字, so that 我能直接读出这一招的回报
13. As a 玩家, I want to 木桩被命中时闪白一下, so that 命中判定无歧义
14. As a 玩家, I want to 木桩有血量并在归零后重置, so that 我可以持续练习连段
15. As a 玩家, I want to 尖刺陷阱触发前有明显的视觉前摇, so that 我能读招并计划翻滚时机
16. As a 玩家, I want to 用翻滚穿过陷阱的判定而不受伤, so that i-frame 的价值被真实验证
17. As a 玩家, I want to 被陷阱命中时扣血、闪白并被击退, so that 敌方攻击有真实的威胁感
18. As a 玩家, I want to 屏幕上看到自己的 HP 条, so that 我能感知风险
19. As a 玩家, I want to HP 归零后场景整体重置, so that 我能立刻开始下一轮验证
20. As a 玩家, I want to 相机以固定俯角跟随我, so that 我能看清动作纵深和场地
21. As a 开发者, I want to 招式（动画、三段时长、派生关系、伤害、前冲）全部由数据表定义, so that 加新招不改代码
22. As a 开发者, I want to 动作系统的全部规则（承诺/派生/缓冲/i-frame）在一个不依赖场景树的纯逻辑模块里, so that 我能写快速单元测试锁定规则
23. As a 开发者, I want to 动画来自 Mixamo 重定向、按招式数据表替换, so that 换动画不动逻辑
24. As a 开发者, I want to demo 跑起来后能亲手验证"承诺感与手感是否成立", so that 我能决定是否投入完整开发

## Implementation Decisions

- **3D 场景化**：项目从 2D 配置转为 3D 场景。玩家为 CharacterBody3D，移动与判定在水平面（XZ 平面坐标）上进行。现有 3D 模型（Kachujin）与 Mixamo 动画库（attack_by_sword / run / walk / standard）复用，缺的招式动画从 Mixamo 下载重定向补齐。倾斜俯视角跟随相机（约 50–60° 俯角、不旋转）。
- **缝 A — 动作状态机**：动作承诺、派生、输入缓冲、i-frame 的全部规则放进一个不依赖场景树的纯逻辑模块。输入为（轻/重/滚输入事件 + tick 推进的时间），输出为（当前招式、当前阶段、此刻可派生/可翻滚）。招式数据表驱动：每个招式声明前摇/判定/后摇时长、派生表、伤害、前冲速度。攻击位移优先取动画根运动（hips 轨道，视觉与物理同源防闪现），前冲速度为无根位移时的兜底。
  - 阶段机：自由 → 前摇（锁死，拒绝一切取消）→ 判定 → 后摇（派生窗口开放，可被派生或翻滚取消）→ 自由。
  - 输入缓冲：派生窗口之外的攻击输入进入暂存队列，进入派生窗口时按表消费。
  - 翻滚规则：前摇内拒绝；后摇与自由状态可立即执行；翻滚自带 i-frame 时间窗。
- **缝 B — 物理判定**：命中判定用 Godot 物理（Area3D 攻击判定框/受击框）。玩家攻击在判定阶段激活 hitbox，与木桩 hurtbox 重叠即结算。
- **命中反馈**：顿帧（命中瞬间全局短暂暂停数帧）、击退（对木桩施加水平冲量）、伤害数字飘字（面向相机的浮动文字）、受击闪烁（材质瞬时变白）。均为命中结算的副作用，不侵入状态机。
- **尖刺陷阱**：定时循环触发；触发前有可读前摇（视觉预告，如尖刺升起/变色），随后激活伤害判定一段时间。零 AI、零动画骨架需求。
- **玩家 HP 与重置**：HP 条 UI；归零后整体重置场景（reload），无死亡演出。
- **像素化渲染推迟**：视口与渲染管线本阶段不做像素化处理（《尘之回声》方向留待玩法验证通过后）。

## Testing Decisions

- **只测外部行为**：断言可观察输出（状态机的阶段与取消可用性、木桩 HP 变化、受击调用），不测内部计时器与私有字段。
- **缝 A 单元测试**（主力）：直接实例化动作状态机、手动推时间，锁定全部规则——前摇内翻滚被拒绝、后摇内派生查表命中、缓冲在窗口消费、i-frame 窗口边界。不依赖场景树，毫秒级。
- **缝 B 集成测试**：用仓库的编辑器内测试套件（`tests/` 下 test_*.gd 约定）搭测试场景：玩家攻击木桩 → HP 减少、顿帧被调用；翻滚 i-frame 内穿过激活的陷阱判定 → 不扣血；站立穿过 → 扣血。
- **先例**：仓库目前无测试，本 spec 建立首个测试先例。
- **不进自动化**：动画观感、飘字样式、相机跟随顺滑度、"手感是否成立"——人工运行验证（user story 24）。

## Out of Scope

- 耐力条、蓄力攻击（明确推迟的 MH 要素）
- 任何敌人 AI（木桩不还手，陷阱零逻辑）
- 像素化渲染、光照氛围、场景装饰
- 多武器系统、武器切换、部位破坏
- 手柄支持、音频、菜单/暂停界面、存档
- 死亡演出（直接场景重置）

## Further Notes

- 建议的首张 tracer 票：**"玩家能用一段轻攻击命中木桩并出现顿帧与扣血"**——它打通 缝A→动画→物理→反馈 的最小闭环，之后每张票在这条线上加深。
- Mixamo 动画的观感是"网络素材感"，本 demo 接受；节奏手感由招式数据表的时长参数决定，与动画质量解耦。
- 验收的最终一环是人工试玩：如果规则全部自动化测试通过但玩起来没有"承诺感"，按测试结论调数据表参数，而不是改规则结构。
